# 下一阶段协同回传算法设计说明

## 1. 文档边界

本文只描述下一阶段的候选设计，不实现新算法，也不改变当前信道、队列、时隙、节点在线或三种直接回传基线。现有代码已经支持：读取固定轨迹和采集事件、逐时隙生成可复现信道快照、评价给定的直传或多跳安排、同步更新源端/中继队列，并统计完整交付、时延、积压和缓存违规。现有人工多跳测试用于验证仿真器语义，不能解释为已经完成协同中继优化。

## 2. 优化问题

研究目标是降低完整数据单元从采集完成到基站完整接收的端到端时延，同时保持较高的完整单元交付率并满足全部物理与队列约束。主要目标建议采用所有数据单元的平均完成时延；只有全部单元完成时该指标才有定义。存在未完成单元时，应报告交付率、未交付bit数、残留位置和已完成单元条件时延，不能删除未完成样本来降低平均时延。

每个时隙需要联合决定：

1. 哪些无人机发送、哪些节点接收；
2. 数据直接发往基站，还是发送给候选中继；
3. 每条活动链路使用哪个子信道；
4. 每条链路从发送端FIFO队列传输哪些数据单元及多少bit。

功率维持当前固定值，不作为优化变量。

## 3. 可用信息与因果边界

时隙开始时，算法可使用：当前节点位置和整时隙在线资格、当前缓存及各数据单元剩余量、采集时间和来源、当前时隙信道快照、各无人机已知返航时刻、固定轨迹给出的未来位置与未来在线区间。

预设轨迹使未来几何位置、遮挡几何和通信退出时间可知。当前信道实现中的阴影衰落与散射项按时隙独立抽样，因此算法不能把未来随机信道实现当作已知量。设计或评估在线算法时，只能使用当前和历史随机信道；如果后续研究离线全知上界，必须单独标明其使用了未来实现，不能与在线算法直接等同。

## 4. 必须满足的约束

- 数据因果：时隙末新采集或新接收的数据最早下一时隙发送。
- 存量约束：发送量不超过时隙开始时发送端持有量；基站累计接收不超过原始数据量。
- 链路容量：每条链路传输量不超过统一 `evaluate_schedule` 给出的速率乘以时隙长度。
- 半双工：无人机每时隙最多参与一条发送或接收链路，不能同时收发。
- 子信道：每架无人机最多使用一个子信道；基站每个子信道最多接收一条链路；同频链路按现有交叉信道增益产生干扰。
- 在线资格：只有整个时隙内均在线的无人机可参与调度；返航后残留数据保留但不能发送或中继。
- 缓存：源数据与中继数据共同占用有限缓存；超限标记为不可行，不能静默丢弃或扩容。
- 数据唯一性：转发是守恒移动或向基站累计接收，不能复制数据或重复计算已经送达的bit。
- 基站角色：基站只接收，不发送。

## 5. 直接回传与中继的统一判断

直接回传减少跳数、排队和资源占用，应始终作为候选动作。中继只在预计收益覆盖额外代价时采用。候选中继的判断至少考虑：源到基站当前速率、源到中继速率、中继未来到基站的可服务机会、双方剩余在线时间、中继已有积压、额外占用的第二个发送时隙、对其他链路造成的同频干扰以及中继缓存余量。

一个可审阅的启发式收益量可以比较：

`预计直传完成时间` 与 `源到中继等待及发送 + 中继排队 + 中继到基站等待及发送`。

该估计只能使用可知轨迹和当前/历史信道统计。估计为正并不保证实际改善，因此实验仍需与直接回传基线在同一输入和同一随机信道快照上比较。

## 6. 初步求解流程

1. **构造可行节点集合**：删除本时隙非整时隙在线、空队列和即将退出且无法完成候选传输的节点。
2. **构造候选链路**：为每个发送端保留直达基站链路，并按距离、当前增益、接收端缓存余量和剩余在线时间筛选少量中继链路。
3. **计算动作评分**：以FIFO队首数据的等待年龄、剩余量、预计直传完成时间、候选中继端积压和退出风险形成可解释评分。评分中显式扣除额外一跳和资源占用。
4. **生成冲突图**：标记共享无人机、违反半双工、同一基站子信道冲突及其他不合法组合。
5. **选择本时隙链路与子信道**：先研究确定性的贪心或小规模组合搜索，按评分加入不冲突动作；每次候选比较复用同一信道快照。
6. **统一评价与队列更新**：把最终安排交给现有 `evaluate_schedule` 和 `ReturnSimulation`，不另写队列更新逻辑。
7. **记录不可行性**：缓存超限、节点退出残留、未完成单元和数据守恒误差按现有规则完整输出。

这一流程用于建立可解释、可回归的首个协同基线。现阶段不选择复杂强化学习结构，不宣称全局最优，也不预设算法创新性已经成立。

## 7. 公平比较

所有方法必须读取同一份 `paper2_baselines/direct_return/input/input_ref_5to10mbit_v10`，使用相同轨迹、采集事件、逐单元大小、在线状态、信道种子、功率、带宽、缓存和仿真时域。同一时隙比较候选调度时必须复用同一信道快照。算法不能重新抽样数据量、延长在线时间、自动交付退出节点数据或调整物理参数。

后续每个待测算法建立 `paper2_algorithms/<algorithm_name>/`，目录内同时放算法代码、专属README和 `results/`。算法应导入 `paper2_model` 的信道与统一队列接口，不复制或改写公共模型，也不把新实验脚本放进 `paper2_model/` 或 `paper2_baselines/`。

基线至少包括现有速率贪心、轮询和最老数据优先。主要报告：完整单元交付率、bit交付比例、全部完成时的平均时延、已完成样本数及条件平均/P95/最大时延、首次发送前等待、首次发送后至完成时间、最终残留、峰值系统积压、单机峰值缓存、缓存违规和数据守恒。若各方法完成集合不同，同时报告全体分母结果和共同完成集合结果，并说明共同集合存在选择偏差。

## 8. 后续实现前需要审阅的问题

- 论文主目标采用全体平均完成时延，还是交付率约束下的时延目标；
- 对未完成单元采用硬约束、惩罚项还是分层目标；
- 候选中继筛选数量与计算预算；
- 预计未来速率使用当前值、历史统计还是仅使用几何大尺度增益；
- FIFO是否作为所有算法固定规则，还是允许在后续单独研究数据单元选择。
